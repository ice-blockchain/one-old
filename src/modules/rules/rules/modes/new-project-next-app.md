# New Project Profile — Next.js App Router

Apply only when `CompiledArchitectureV1.profile.profileId=next-app`. The
compiled profile chooses `<web-root>/app` or `<web-root>/src/app` from immutable
baseline evidence; the absence of Pages Router evidence selects App Router for
a new project.

```
<web-root>/
├── package.json
├── next.config.ts
├── tsconfig.json
├── postcss.config.mjs                     Tailwind v4 PostCSS plugin
├── next-env.d.ts                          regenerated by next build
├── messages/en.json                       source-locale i18n catalog
├── app/ | src/app/
│   ├── layout.tsx                         app-shell/entrypoint
│   ├── globals.css                        design tokens + Tailwind entry
│   └── <route segments>/page.tsx          compiled page modules
├── components/ | src/components/          compiled components
├── features/ | src/features/              <name>/index.ts
├── lib/ | src/lib/                        UI-local service/store modules
└── public/                                 crawl/share asset set
```

Styling lives in the compiled `globals.css` (imported once from
`layout.tsx`) plus Tailwind utility classes — never in `<style>` tags or
per-component inline CSS blobs. User-facing copy goes through the
`messages/en.json` catalog per `rules/frontend/i18n.md`; do not hardcode UI
strings in components.

Route parameters compile from `:id` or `{id}` to `[id]`; `/` compiles to the
selected app root's `page.tsx`. Do not add Pages Router, duplicate `app` and
`src/app`, or create a route registry for file routes.

The framework scaffold includes `package.json`, `next.config.ts`,
`tsconfig.json`, and the public crawl/share assets listed in
`rules/modes/new-project-architecture.md`. The catalog's repository/tooling,
environment, backend, and web-QA overlays also apply. Browser-visible external
API configuration uses `NEXT_PUBLIC_API_URL`; server-only code uses `API_URL`.

`profile.sourceRoots`, the selected entrypoint, compiled module outputs, and
`allowedOutputs` are authoritative. Eligible implementers create only their
work-unit paths; an absent middleware, route handler, provider, config, or
asset requires a recompile.
