# Frontend i18n Baseline

Localization is not optional polish. Generated UI, changed UI, and existing
web/native surface reconciliation must integrate with the project's i18n system
even when the user did not explicitly ask for translations.

## Detection Before UI Writes

Before creating or changing pages, features, components, routes, layouts, forms,
empty states, errors, navigation, or setup banners:

- Inspect the active project for an i18n module: `packages/i18n`, `src/i18n*`,
  `app/i18n*`, `locales/`, `public/locales/`, `messages/`, catalog JSON/TS
  files, `i18next`, `react-i18next`, `expo-localization`, or an existing
  provider wrapper.
- If an i18n module exists, extend that exact module and catalog shape. Do not
  create a parallel translation system.
- New Traffic One React/Vite, Ionic, and React Native projects use
  `packages/i18n` by default and wire the provider before feature UI is
  scaffolded.
- If no frontend or user-facing copy is touched, record
  `i18n baseline: Not applicable` with the reason.

## Implementation Rules

- All visible text, placeholders, form labels, validation errors, loading,
  empty, error, offline/degraded, permission-denied, button/menu/tab labels,
  image alt text, ARIA labels, live-region copy, and accessibility hints use
  translation keys.
- Add source-language catalog entries for every key introduced in the same
  change. Do not leave placeholder keys or untranslated fallback strings in
  production UI.
- **Use `<Trans>` over `t()` for any copy that is more than a bare scalar string.**
  `t()` is ONLY for simple scalars rendered as a whole — plain labels, `aria-label`/
  `placeholder`/`title` attributes, validation messages, `document.title`. The moment copy
  contains embedded markup or components (links, `<code>`, `<strong>`, line breaks), nested
  elements, or rich interpolation, it MUST use `<Trans>` from `react-i18next` — never
  `t()` with manual concatenation or `dangerouslySetInnerHTML`. Examples:
  - scalar → `{t('nav.signOut')}` (also fine: a whole link/button whose visible text is one scalar — `<Link to="/signup">{t('nav.signup')}</Link>`)
  - **sentence with an inline link/element — THE most common rich case; do NOT split it into `t()` fragments:**
    - ❌ `{t('login.noAccount')} <Link to="/signup">{t('login.signupLink')}</Link>` ("Don't have an account? Sign up" split across two keys — breaks word order in other languages)
    - ✅ `<Trans i18nKey="login.noAccount" components={{ signup: <Link to="/signup" /> }}>Don't have an account? <signup>Sign up</signup></Trans>`
  - embedded components → `<Trans i18nKey="setup.description" ns="common" components={{ supabaseUrl: <code>VITE_SUPABASE_URL</code>, anonKey: <code>VITE_SUPABASE_ANON_KEY</code> }} />`
  - **Self-check before you finish:** any JSX text node that mixes text with an inline `<Link>`/`<a>`/`<strong>`/`<em>`/`<code>`/`<br>` is rich copy → one `<Trans>`, never a `{t(...)}` fragment sitting next to the element. If a UI renders any such sentence but never imports `Trans` from `react-i18next`, that is a violation.
- **Always give `<Trans>` a children fallback** = the source-language default, e.g.
  `<Trans i18nKey="test">Test</Trans>`. The children render if the key is missing and double
  as the extractable default (`defaultValue`), so the UI never shows a raw key or blank. Every
  new `<Trans>` ships its source-language children + the matching catalog entry.
- Do not concatenate translated fragments. Use complete phrases with
  interpolation values.
- Hardcoded UI strings are allowed only for brand names, user-generated or
  server-provided content, technical IDs, route params, analytics event names,
  and test fixtures.
- Missing-config banners and setup CTAs, including EnvBanner-like components,
  also use translation keys; the setup link target itself remains the literal
  `https://traffic.io/`.

## Review And Test Gate

Reviewers request changes when changed UI ignores an existing i18n module, ships
hardcoded user-facing strings, omits catalog entries, concatenates translated
fragments, uses `t()` for rich copy that should be rendered with `<Trans>`, or
ships a `<Trans>` without a source-language children fallback. **Concrete tell to
grep for:** a translated fragment `{t(...)}` sitting next to an inline
`<Link>`/`<a>`/`<strong>`/`<em>`/`<code>` in the SAME JSX text node (e.g.
`{t('x')} <Link>{t('y')}</Link>`) is a split sentence → it must be one `<Trans>`.
A UI that renders such sentences but never imports `Trans` is failing this gate.
Testers assert user-visible behavior through accessible names and labels from
the rendered UI rather than private translation internals.
