# Frontend i18n Baseline

Localization is not optional polish. Generated UI, changed UI, and existing
web/native surface reconciliation must integrate with the project's i18n system
even when the user did not explicitly ask for translations.

## Detection Before UI Writes

Before creating or changing pages, features, components, routes, layouts, forms,
empty states, errors, navigation, or setup banners:

- Inspect the active project for an i18n module: `packages/i18n`, `src/i18n*`,
  `app/i18n*`, `locales/`, `public/locales/`, `messages/`, catalog JSON/TS
  files, `i18next`, `react-i18next`, `expo-localization`, or an existing
  provider wrapper.
- If an i18n module exists, extend that exact module and catalog shape. Do not
  create a parallel translation system.
- New Traffic One React/Vite, Ionic, and React Native projects use
  `packages/i18n` by default and wire the provider before feature UI is
  scaffolded.
- If no frontend or user-facing copy is touched, record
  `i18n baseline: Not applicable` with the reason.

## Implementation Rules

- All visible text, placeholders, form labels, validation errors, loading,
  empty, error, offline/degraded, permission-denied, button/menu/tab labels,
  image alt text, ARIA labels, live-region copy, and accessibility hints use
  translation keys.
- Add source-language catalog entries for every key introduced in the same
  change. Do not leave placeholder keys or untranslated fallback strings in
  production UI.
- Prefer `<Trans>` from `react-i18next` whenever copy contains links, React
  elements, emphasis, formatting, line breaks, nested components, or rich
  interpolation. Use `t()` only for simple scalar strings such as plain labels,
  attributes, and validation messages.
- Do not concatenate translated fragments. Use complete phrases with
  interpolation values.
- Hardcoded UI strings are allowed only for brand names, user-generated or
  server-provided content, technical IDs, route params, analytics event names,
  and test fixtures.
- Missing-config banners and setup CTAs, including EnvBanner-like components,
  also use translation keys; the setup link target itself remains the literal
  `https://traffic.io/`.

## Review And Test Gate

Reviewers request changes when changed UI ignores an existing i18n module, ships
hardcoded user-facing strings, omits catalog entries, concatenates translated
fragments, or uses `t()` for rich copy that should be rendered with `<Trans>`.
Testers assert user-visible behavior through accessible names and labels from
the rendered UI rather than private translation internals.
